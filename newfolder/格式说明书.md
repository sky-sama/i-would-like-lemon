# 卡牌对战引擎 - 自定义牌组编写指南（JSON）

本文档面向熟悉 JavaScript 与 JSON 的开发者，详细说明如何为游戏引擎编写自定义牌组文件（.json）。阅读本指南后，您可以将任意文本描述的卡牌套组转换为引擎可读取的格式，实现丰富的卡牌效果。

---

## 1. 牌组文件整体结构

```json
{
  "name": "套牌名称（可选）",
  "fieldDefinitions": { ... },
  "playerBindings": { ... },
  "abilities": { ... },
  "cards": [ ... ]
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `name` | string | 套牌显示名称，仅用于标识，不影响游戏逻辑。 |
| `fieldDefinitions` | object | 定义所有**角色字段**（如生命、魔法、护甲、先攻等）的类型与上下限。 |
| `playerBindings` | object | 为玩家角色绑定初始字段值。 |
| `abilities` | object | **全局能力**（对所有玩家/卡片生效的规则，如护甲减伤、炸弹倒计时等）。 |
| `cards` | array | 卡牌定义列表，每张卡可设置数量（quantity）。 |

---

## 2. 角色字段系统（`fieldDefinitions`）

角色（Player）拥有动态字段系统。每个字段可以是 **数值（value）**、**关键词（keyword）** 或 **计数器（counter）**。

### 2.1 字段定义语法

```json
"fieldDefinitions": {
  "hp": { "type": "value", "max": 20, "min": 0 },
  "mp": { "type": "value", "max": 3, "min": 0 },
  "先攻": { "type": "value" },
  "护甲": { "type": "value" },
  "冰冻": { "type": "keyword" },
  "炸弹": { "type": "counter" }
}
```

- **value**：整数数值，可设置 `max`/`min`（可选）。使用modify修改时会自动钳制，但使用set设置时无视。
- **keyword**：布尔值（true/false），表示是否拥有该关键词。设置为false和不拥有该字段效果相同。
- **counter**：特殊的字典结构，用于存储按效果ID分离的计数器（例如“炸弹倒计时”、“增益层数”）。

### 2.2 玩家初始绑定（`playerBindings`）

为玩家设置字段的初始值。必须为 `hp` 提供初始生命值，也应为`mp`和`先攻`设置初值，其他可选（不拥有默认为0，首次修改时会自动添加）。

```json
"playerBindings": {
  "hp": 20,
  "mp": 3,
  "先攻": 1,
  "护甲": 0,
  "冰冻": false
}
```

对于 `counter` 类型字段，不应在这里赋初始值（计数器通过能力动态添加）。

## 3. 全局能力（`abilities`）

全局能力注册在套牌的 `abilities` 对象中，一旦游戏开始就会监听指定事件，并可影响所有玩家和卡片。例如护甲减伤、炸弹倒计时、回合开始抽牌等都属于全局能力。

### 3.1 能力对象结构

```json
"abilities": {
  "能力名称": {
    "triggers": ["事件1", "事件2"],
    "priority": 100,
    "condition": "(ctx) => { return true; }",
    "action": "(ctx) => { ... }"
  }
}
```

| 属性 | 说明 |
|------|------|
| `triggers` | 数组，表示该能力在哪些事件发生时触发。 |
| `priority` | 数字，越大越先执行。引擎中同一次事件按优先级降序执行。遇到 `preventDefault()` 且下一个能力优先级 ≤0 时会中断。 |
| `condition` | 字符串形式的函数体，接收 `ctx`（AbilityContext）参数，返回 `boolean`。不写或返回 `true` 时才会执行 `action`。 |
| `action` | 字符串形式的函数体，接收 `ctx`（AbilityContext），执行效果。 |

> 引擎会使用 `eval()` 将函数字符串还原为真实函数，因此您可以自由编写 JavaScript 代码，但注意闭包范围仅限于 `ctx` 及全局 API。

### 3.2 可用的事件（trigger）列表

| 事件名 | 触发时机 | 上下文补充 |
|--------|----------|------------|
| `game_start` | 游戏开始，洗牌前 | `ctx.player` = 玩家1, `ctx.target` = 玩家2 |
| `turn_start` | 每回合开始时 | `ctx.player` = 当前回合玩家 |
| `turn_end` | 每回合结束时 | `ctx.player` = 结束回合的玩家 |
| `draw` | 抽牌后（包括任何抽牌效果） | `ctx.card` = 抽到的卡牌实例 |
| `play_check` | 尝试使用卡牌前（费用、回合、特殊限制。注意，此方法也会在更新UI期间调用，因此避免在这里写入动作。） | `ctx.card` = 待使用的卡牌；可调用 `ctx.preventDefault(reason)` 禁止出牌 |
| `before_play` | 通过 `play_check` 后（扣除费用时） | `ctx.card` = 使用的卡牌 |
| `on_play` | **卡片自身能力**，写在卡牌定义中 | `ctx.player` = 使用方，`ctx.target` = 对手 |
| `after_play` | 卡片使用后（弃牌时） | `ctx.card` = 使用的卡牌 |
| `${name}_change` | 玩家的 `${name}` 字段变化时 | `ctx.target` = 玩家对象，`ctx.data.old` / `ctx.data.new` 变化前后的值 |
| `fatigue_shuffle` | 抽牌堆为空且准备洗入弃牌堆时 | `ctx.player` = 需要洗牌的玩家 |

> ⚠️ 注意：函数字符串内的代码会被 `eval()` 执行，请确保代码安全且无语法错误。

## 4. 卡牌定义（`cards` 数组）

每张卡牌是一个对象，可以定义名称、字段（费用）、能力、描述和数量。

```json
{
  "name": "卡牌名称",
  "fields": [ { "name": "cost", "type": "value", "value": 1 } ],
  "description": "卡牌描述文本",
  "abilities": [ ... ],
  "quantity": 3
}
```

### 4.1 卡牌字段 `fields`

`fields` 数组用于定义卡牌的静态字段，目前支持两种：

- type为value代表数值字段，其中游戏引擎为**`cost`**（类型 `value`）预设了自动进行费用检查和扣除的能力。
- type为keyword代表关键词字段。

以上均可在能力中通过 `card.definition.getStaticValue` 读取，同样可用modifyStaticValue和setStaticValue修改。

示例：
```json
"fields": [
  { "name": "cost", "type": "value", "value": 2 },
  { "name": "攻击力", "type": "value", "value": 3 }
]
```

### 4.2 卡牌能力 `abilities`

与全局能力结构相同，但触发器只能为 `["on_play"]`。卡片能力会在对应时刻执行。对于要使用其他触发器的效果，请使用对关键词生效的全局能力，并将该关键词赋予该卡牌。

```json
"abilities": [
  {
    "triggers": ["on_play"],
    "action": "ctx.game.heal(ctx.player, 5);"
  }
]
```

## 5. 能力上下文（`ctx`）详解

在 `condition` 和 `action` 中，您可以使用唯一的参数 `ctx`（AbilityContext）。它提供了丰富的属性和方法来操作游戏状态。

### 5.1 核心属性

| 属性 | 类型 | 说明 |
|------|------|------|
| `ctx.game` | GameEngine | 游戏主引擎实例，可调用各种游戏级方法。 |
| `ctx.player` | Player | 当前能力关联的“主动方”（通常出牌玩家或触发事件的玩家）。 |
| `ctx.target` | Player / CardInstance | 能力关联的“目标”。对于伤害类卡牌，通常指对方玩家；对于全局事件则依情况而定。 |
| `ctx.card` | CardInstance | 当前触发能力的那张卡牌（例如抽到的牌、使用的牌）。 |
| `ctx.data` | object | 额外数据，如 `${name}_change` 事件中的 `{ old, new }`。 |

### 5.2 常用游戏动作方法（通过 `ctx.game`）

```javascript
// 造成伤害（自动触发 hp_change 事件）
ctx.game.dealDamage(玩家对象, 伤害数值);

// 恢复生命（自动触发 hp_change）
ctx.game.heal(玩家对象, 恢复数值);

// 移动卡牌（改变区域：'hand', 'field', 'discard', 'banished', 'deck'）
ctx.game.moveCard(卡牌实例, 'discard');

// 添加日志（type 可选：'system', 'damage', 'heal', 'mp'）
ctx.game.log("消息内容", "类型");

// 检查游戏是否结束（通常由 hp_change 自动触发，也可手动调用）
ctx.game.checkGameOver();

// 结束回合（很少直接在能力中调用）
ctx.game.endTurn();
```

### 5.3 玩家对象（`Player`）可用方法

```javascript
// 获取字段值（数值、关键词（返回0/1）、计数器总和）
let hp = player.getFieldValue('hp');
let hasFrozen = player.getFieldValue('冰冻') > 0;

// 设置数值字段（不会自动钳制 max/min）
player.setFieldValue('mp', 5);

// 修改数值字段（正负增量，被 max/min 限制）
player.modifyFieldValue('护甲', 2);

// 设置关键词
player.setKeyword('冰冻', true);

// 检查关键词
if (player.hasKeyword('冰冻')) { ... }

// 计数器操作（需要提供效果ID）
player.setCounter('炸弹', effectId, 10);
player.modifyCounter('炸弹', effectId, -1);
let count = player.getCounter('炸弹', effectId);      // 指定效果ID的计数
let total = player.getCounterSum('炸弹');             // 所有效果ID的总和
player.removeCounter('炸弹', effectId);               // 移除该效果ID的计数

// 抽牌
player.draw(数量);

// 弃置所有手牌（通常用于回合开始时）
player.discardAllHand();

// 洗牌（抽牌堆）
player.shuffleDeck();

// 查看区域数组
let hand = player.hand;          // 直接访问数组
let deck = player.getZoneArray('deck');  // 其他区域
```

### 5.4 卡牌实例（`CardInstance`）可用方法

```javascript
// 获取卡牌定义的静态字段值
let cost = card.definition.getCost();                     // 自动读取 cost
let attack = card.definition.getStaticValue('攻击力');

// 检查卡牌是否有关键词（定义时）
if (card.definition.hasKeyword('疲劳')) { ... }

// 计数器（类似玩家计数器，按效果ID存储）
card.setCounter('充能层数', effectId, 3);
card.modifyCounter('充能层数', effectId, 1);
let value = card.getCounter('充能层数', effectId);
let sum = card.getCounterSum('充能层数');

// 修改卡牌的动态数值字段（例如临时改变费用）
card.definition.modifyStaticValue('攻击力', 2);
```

### 5.5 特殊动作：生成新卡牌

生成一个全新的卡牌实例并加入到玩家的区域（如手牌、抽牌堆）。例如实现“生成一张衍生卡”。

```javascript
// 1. 创建卡牌定义（注意：定义需符合卡片定义结构）
const tokenDef = new CardDefinition({
  name: '小精灵',
  fields: [{ name: 'cost', type: 'value', value: 0 }],
  abilities: [{
    triggers: ['on_play'],
    action: 'ctx.game.heal(ctx.player, 2);'
  }]
});

// 2. 创建实例，指定拥有者
let tokenCard = new CardInstance(tokenDef, 拥有者玩家);

// 3. 加入手牌（或其它区域）
拥有者玩家.hand.push(tokenCard);
tokenCard.zone = 'hand';

// 4. 可选：触发抽牌事件等
ctx.game.emit('draw', new AbilityContext(ctx.game, 'draw', 拥有者玩家, 对手玩家, tokenCard));
```

其他作法：在json中直接定义卡牌并将数量设为0，然后使用 `new CardInstance(cardDefinition, owner)` 并手动添加到区域数组。

### 5.6 阻止效果与事件链

在 `play_check` 或其它需要拦截的能力中，使用 `ctx.preventDefault(reason)` 来阻止后续执行。

```javascript
// 示例：检查目标是否拥有“无敌”关键词
if (ctx.target.hasKeyword('无敌')) {
  ctx.preventDefault("目标无敌，无法造成伤害");
}
```

被阻止后，后续能力（优先级≤0的）将不再执行。
`play_check` 被阻止后，卡牌不能被使用。

## 6. 能力编写最佳实践与示例

### 6.1 伤害与治疗

```json
{
  "name": "火焰冲击",
  "fields": [{ "name": "cost", "type": "value", "value": 2 }],
  "description": "对敌方造成4点伤害",
  "abilities": [{
    "triggers": ["on_play"],
    "action": "ctx.game.dealDamage(ctx.target, 4);"
  }],
  "quantity": 3
}
```

### 6.2 恢复魔法值

```json
{
  "name": "冥想",
  "fields": [{ "name": "cost", "type": "value", "value": 0 }],
  "abilities": [{
    "triggers": ["on_play"],
    "action": "ctx.player.modifyFieldValue('mp', 2); ctx.game.log('恢复了2点MP', 'mp');"
  }]
}
```

### 6.3 检索/抽特定卡（移动卡牌）

```json
{
  "name": "寻找武器",
  "fields": [{ "name": "cost", "type": "value", "value": 1 }],
  "abilities": [{
    "triggers": ["on_play"],
    "action": "let weapon = ctx.player.deck.find(c => c.definition.name === '长剑'); if (weapon) { ctx.game.moveCard(weapon, 'hand'); ctx.game.log('抽到了长剑'); }"
  }]
}
```

> 注意：`moveCard` 会自动处理从原区域移除并添加到新区域。其他区域字符串：`'hand'`，`'deck'`，`'discard'`，`'banished'`，`'field'`。

### 6.4 计数器效果（倒计时炸弹）

**全局能力**（放在套牌的 `abilities` 中）：
```json
"炸弹倒计时": {
  "triggers": ["after_play"],
  "priority": 5,
  "action": "let bombField = ctx.player.fields['炸弹']; if (!bombField || bombField.type !== 'counter') return; for (let effectId in bombField.values) { let val = bombField.values[effectId]; if (val > 0) { ctx.player.modifyCounter('炸弹', effectId, -1); if (ctx.player.getCounter('炸弹', effectId) <= 0) { ctx.player.removeCounter('炸弹', effectId); ctx.game.dealDamage(ctx.player, 10); ctx.game.log(`${ctx.player.name} 的炸弹爆炸了！`, 'damage'); } } }"
}
```

**卡牌**（给对手放置炸弹）：
```json
{
  "name": "定时炸弹",
  "fields": [{ "name": "cost", "type": "value", "value": 2 }],
  "abilities": [{
    "triggers": ["on_play"],
    "action": "let effectId = Math.random().toString(36).substr(2, 8); ctx.target.setCounter('炸弹', effectId, 10); ctx.game.log(`${ctx.target.name} 被放置了炸弹（倒计时10）`, 'system');"
  }]
}
```

### 6.5 全局护甲减伤（全局能力）

```json
"格挡伤害": {
  "triggers": ["hp_change"],
  "priority": 10,
  "condition": "return ctx.target.getFieldValue('护甲') > 0 && ctx.data.new < ctx.data.old;",
  "action": "let oldHp = ctx.data.old, newHp = ctx.data.new; let armor = ctx.target.getFieldValue('护甲'); let damage = oldHp - newHp; if (damage > armor) { ctx.target.setFieldValue('hp', oldHp - armor); ctx.target.setFieldValue('护甲', 0); } else { ctx.target.modifyFieldValue('护甲', -damage); ctx.target.setFieldValue('hp', oldHp); }"
}
```

### 6.6 场地区域与永久物（例如持续增益）

引擎支持 `field` 区域（场地牌），您可以将卡牌移动到 `'field'` 区域。配合 `turn_start` 等全局事件，实现基于场地牌的触发效果。

### 6.7 疲劳机制

引擎内置疲劳机制：当抽牌堆为空且需要抽牌时，会将弃牌堆洗入并生成一张“疲劳”卡。您可以在全局能力中重写或扩展疲劳行为。

## 8. 注意事项与限制

1. **函数字符串的写法**  
   字符串内容必须是一个合法 JavaScript 语句块。使用 `ctx` 提供的 API，不要引用外部未定义的变量。**禁止使用 `alert`、`prompt` 等阻塞性函数**。

2. **计数器效果ID**  
   在设置计数器时，请使用generateId()生成唯一的效果ID，以便多个相同效果可以独立计数。

3. **字段修改触发事件**  
   对玩家字段（如 `hp`、`mp`）使用 `setFieldValue` / `modifyFieldValue` 会自动触发 `hp_change` 等对应事件。直接获取field并修改不会触发事件，请酌情考虑。

4. **区域移动**  
   请使用 `ctx.game.moveCard(card, toZone)`，这保证了卡牌的 `zone` 属性同步更新。不要手动 `splice` 和 `push` 同时忘记修改 `zone`，否则事件监听可能出错。

5. **回合流程**  
   内置规则：  
   - 先攻决定后，先手玩家开始第一回合。  
   - 每回合开始时（第2回合起），当前玩家会弃置所有手牌，然后抽5张牌。  
   - MP 会在回合开始时重置到最大值（如果定义了 `mp` 且设置了 `max`）。  
   - 费用检查和扣除由全局能力自动完成，您只需在卡片中定义 `cost` 即可。  
   如果您希望改变这些规则，可以通过重写对应的全局能力（如 `turn_start` 中的 `MP恢复` 能力）并提高优先级来覆盖。

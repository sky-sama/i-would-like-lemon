# 卡牌对战引擎 — 自定义套组格式规范

> 本文档面向熟悉 JavaScript 与 JSON 的套组设计者。通过阅读本文，你可以在不接触引擎源码的情况下，将任意卡牌游戏的规则文本转化为引擎可读取的 JSON 套组文件。

---

## 1. 文件根结构

一个合法的套组文件是一个 JSON 对象，包含以下五个顶级字段：

```json
{
  "name": "套组名称",
  "fieldDefinitions": { ... },
  "playerBindings": { ... },
  "abilities": { ... },
  "cards": [ ... ]
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | `string` | 否 | 套组名称，仅用于展示。 |
| `fieldDefinitions` | `object` | **是** | 声明本套组使用的所有字段及其数据类型与约束。 |
| `playerBindings` | `object` | **是** | 定义对战双方玩家开局时的字段初始值。 |
| `abilities` | `object` | 否 | 定义**全局能力**（不绑定于任何单张卡牌，通常用于实现全局规则、持续效果或字段联动）。 |
| `cards` | `array` | **是** | 卡牌定义列表，每张卡可独立携带字段与能力。 |

---

## 2. 字段系统（Field System）

引擎支持三类字段：`value`（数值）、`keyword`（关键词/布尔标记）、`counter`（计数器）。所有字段必须先声明再使用。

### 2.1 fieldDefinitions — 字段声明

```json
"fieldDefinitions": {
  "hp":   { "type": "value", "max": 100, "min": 0 },
  "mp":   { "type": "value", "max": 10,  "min": 0 },
  "护甲": { "type": "value" },
  "先攻": { "type": "value" },
  "中毒": { "type": "counter" },
  "护盾": { "type": "keyword" }
}
```

| 属性 | 适用类型 | 说明 |
|---|---|---|
| `type` | 全部 | `"value"` \| `"keyword"` \| `"counter"` |
| `max` | `value` | **上限**。仅对 `modify` 操作生效；`set` 操作不受此限制（详见第7节）。 |
| `min` | `value` | **下限**。同上，仅约束 `modify`。 |

### 2.2 playerBindings — 玩家初始值

```json
"playerBindings": {
  "hp": 100,
  "mp": 5,
  "先攻": 5,
  "护甲": 0
}
```

- 键名必须与 `fieldDefinitions` 中声明的字段一致。
- 未在 `playerBindings` 中给出初值的字段，引擎会按类型补全默认值：`value` 为 `0`，`keyword` 为 `false`，`counter` 为空映射。
- **强制要求**：`hp` 必须声明为 `value` 类型且必须在 `playerBindings` 中赋初值，否则套组校验失败。

### 2.3 字段类型详解

#### value（数值字段）

- 表示整数数值，如生命值、法力值、攻击力、护甲。
- 支持 `max` / `min` 边界约束，但**仅作用于 `modify` 系列操作**。
- 若要在 UI 中显示为 "当前值/最大值"（如 `5/10`），必须同时提供 `max`。

#### keyword（关键词字段）

- 表示布尔标记，如 `疲劳`、`护盾`、`免疫`。
- 值只有 `true`（拥有）或 `false`（不拥有）。
- 可用于条件判断，例如 `"condition": "ctx => ctx.card.definition.hasKeyword('疲劳')"`。

#### counter（计数器字段）

- **按来源隔离**：每个计数器实例由 `effectId` 区分，同一字段名下可存在多个独立计数器。
- 常用于"中毒层数（每来源独立）"、"炸弹倒计时"、"印记层数"。
- 在 UI 中，若同一字段下存在多个 `effectId`，会显示为 `3|5|2` 的形式；若只有一个，则直接显示数值。

## 3. 卡牌定义（cards）

`cards` 是一个数组，每个元素描述一种卡牌模板及其携带数量：

```json
{
  "name": "火球术",
  "fields": [
    { "name": "cost", "type": "value", "value": 2 }
  ],
  "description": "造成15点伤害",
  "condition": "ctx => ctx.source.getFieldValue('mp') >= 2",
  "abilities": [
    {
      "name": "火球伤害",
      "triggers": ["on_play"],
      "action": "async ctx => { await ctx.game.dealDamage(ctx.target, 15); }"
    }
  ],
  "quantity": 3
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | `string` | **是** | 卡牌名称。 |
| `fields` | `array` | 否 | 卡牌的**静态字段**，如费用、攻击力、耐久。 |
| `description` | `string` | 否 | 卡牌描述文本，仅展示。 |
| `condition` | `function` | 否 | 打出条件。返回 `false` 时该卡无法被点击选中。 |
| `abilities` | `array` | 否 | 卡牌能力列表。 |
| `quantity` | `number` | **是** | 该卡牌在套组中的数量。 |

### 3.1 卡牌静态字段（Card Static Fields）

卡牌字段与玩家字段独立，存储在卡牌定义（`CardDefinition`）上，所有同名卡牌实例共享同一组静态值。

```json
"fields": [
  { "name": "cost",  "type": "value", "value": 2, "max": 5, "min": 0 },
  { "name": "疾速", "type": "keyword" }
]
```

- `type: "keyword"` 的字段在声明时即视为拥有该关键词（值为 `true`）。
- 卡牌静态字段支持运行时 `modify` / `set`，但通常用于实现"本场战斗中攻击力+3"等临时增益。
- **费用（cost）**：若声明了 `cost` 字段，引擎会自动将其注册为打出费用，并在 `play_check` 阶段进行 MP 校验（见第8节）。

## 4. 能力系统（Ability System）

能力是引擎的核心执行单元。能力分为两类：

1. **全局能力**：写在 `deck.abilities` 中，通常用于全局规则、持续效果、字段联动。
2. **卡牌能力**：写在单张卡牌的 `abilities` 数组中，通常用于打出时效果、离场效果等。

### 4.1 能力结构

```json
{
  "name": "能力名称（可选，用于日志与报错）",
  "triggers": ["turn_start", "hp_change"],
  "priority": 50,
  "condition": "ctx => ctx.source.getFieldValue('护甲') > 0",
  "action": "async ctx => { ... }"
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | `string` | 否 | 能力名称。在报错提示与日志中会显示，强烈建议填写。 |
| `triggers` | `string[]` | **是** | 触发事件名列表。当任意一个事件触发时，能力进入执行队列。 |
| `priority` | `number` | 否 | 优先级，**数值越大越先执行**。默认 `0`。用于处理"先扣护甲再扣血"或"先打康再执行"等顺序问题。 |
| `condition` | `function` | 否 | 执行条件。返回 `true` 才执行 `action`。 |
| `action` | `function` | **是** | 实际执行逻辑。可以是普通函数或 `async` 函数。 |

### 4.2 触发器（Triggers）完整列表

引擎在以下时机派发事件，能力可通过 `triggers` 订阅：

#### 游戏流程事件

| 事件名 | 派发时机 | 上下文关键字段 |
|---|---|---|
| `game_start` | 游戏初始化完成，双方玩家与套组就绪后 | `actor` = 玩家1, `source` = 玩家1, `target` = 玩家2 |
| `turn_start` | 新回合开始时（先攻决定后第一回合也会触发） | `actor` = 当前回合玩家, `source` = 当前回合玩家, `target` = 对手 |
| `turn_end` | 当前玩家点击"结束回合"后 | 同上 |
| `draw` | 每次成功抽牌后 | `card` = 抽到的卡牌, `source` = 抽牌玩家, `target` = 对手 |
| `fatigue_shuffle` | 抽牌堆为空，将弃牌堆洗回并加入疲劳卡前 | `data.drawEffect` = `true` |

#### 卡牌使用事件

| 事件名 | 派发时机 | 上下文关键字段 |
|---|---|---|
| `play_check` | 玩家尝试点击卡牌时（校验阶段） | `card` = 被点击的卡牌, `source` = 卡牌拥有者 |
| `before_play` | 卡牌通过所有校验，即将执行效果前 | 同上 |
| `after_play` | 卡牌所有 `on_play` 能力执行完毕后 | 同上 |

#### 能力执行事件（用于"打康"或"连锁"）

| 事件名 | 派发时机 | 上下文关键字段 |
|---|---|---|
| `before_ability_execute` | **任意能力**执行前 | `ability` = 即将执行的能力对象, `data.originalEvent` = 原始事件名, `data.originalAbility` = 原始能力定义 |
| `after_ability_execute` | **任意能力**执行后 | 同上 |

#### 字段变化事件

| 事件名 | 派发时机 | 上下文关键字段 |
|---|---|---|
| `hp_change` | 玩家 `hp` 字段值发生变化后（通过 `setFieldValue` 触发） | `target` = 该玩家, `data.old` = 旧值, `data.new` = 新值 |
| `{fieldName}_change` | **任意自定义字段**值发生变化后 | 同上。例如 `mp_change`、`护甲_change`、`中毒_change` |

> **重要**：`counter` 类型字段的数值变化**不会**自动触发 `{fieldName}_change` 事件。若需要监听计数器变化，请在修改计数器的 `action` 中手动派发事件，或通过 `turn_start` 等固定时机轮询。

#### 卡牌专属触发

| 事件名 | 派发时机 | 上下文关键字段 |
|---|---|---|
| `on_play` | 该卡牌被成功打出时（仅卡牌能力可用） | `card` = 该卡牌实例, `source` = 出牌玩家, `target` = 对手 |

## 5. AbilityContext 完整 API

所有 `condition` 与 `action` 函数均接收一个上下文对象 `ctx`（即 `AbilityContext`）。以下是 `ctx` 的完整属性与方法列表：

### 5.1 上下文属性（只读）

| 属性 | 类型 | 说明 |
|---|---|---|
| `ctx.game` | `GameEngine` | 游戏主引擎实例。通过它可以访问全局状态、调用游戏级方法。 |
| `ctx.event` | `string` | 当前触发的事件名，如 `"turn_start"`。 |
| `ctx.actor` | `Player` | **当前回合的行动玩家**。无论事件由谁触发，`actor` 始终指向"现在轮到谁"。 |
| `ctx.source` | `Player` \| `CardInstance` | **事件的来源**。例如 `draw` 事件中为抽牌玩家；`on_play` 中为出牌玩家。 |
| `ctx.target` | `Player` \| `CardInstance` | **事件的目标**。通常为 `source` 的对手。 |
| `ctx.card` | `CardInstance` \| `null` | 与事件直接关联的卡牌。在 `draw` / `play_check` / `on_play` 中指向具体卡牌。 |
| `ctx.ability` | `object` \| `null` | 仅在 `before_ability_execute` / `after_ability_execute` 中填充，指向即将执行（或已执行）的能力对象。 |
| `ctx.data` | `object` | 事件附加数据。例如 `hp_change` 事件中包含 `{ old, new }`。 |
| `ctx.player` | `Player` | **兼容旧代码**，等同于 `ctx.actor`。 |

### 5.2 上下文方法

| 方法 | 说明 |
|---|---|
| `ctx.preventDefault(reason)` | **阻止默认行为**。只能在 `play_check` 或 `before_ability_execute` 等可拦截阶段调用。调用后，当前正在校验的打出或能力将被取消，并在 UI 中显示 `reason`。 |

### 5.3 快捷字段读写 API

`ctx` 提供统一接口来读写玩家或卡牌上的字段，无需判断对象类型：

#### 读取字段

```javascript
ctx.getField(owner, name, type, id)
```

- `owner`: `Player` 实例或 `CardInstance` 实例。
- `name`: 字段名，如 `"hp"`。
- `type`: `"value"` | `"keyword"` | `"counter"`。
- `id`: `counter` 类型必需，指定 `effectId`。

#### 设置字段

```javascript
ctx.setField(owner, name, value, type, id)
```

- 对 `value` 类型执行**无边界限制**的直接赋值（与 `modify` 不同）。
- 对 `keyword` 类型执行布尔赋值。
- 对 `counter` 类型设置指定 `effectId` 的数值（自动下限为 `0`）。

#### 修改字段

```javascript
ctx.modifyField(owner, name, delta, type, id)
```

- 对 `value` 类型执行**受 `max` / `min` 约束**的增减。例如 `max: 100` 时，`modifyField(player, 'hp', 999)` 实际只会加到 `100`。
- 对 `counter` 类型执行增减（自动下限为 `0`）。

> **关键区别**：`setField` 不受 `max/min` 限制，用于实现"将 MP 恢复至上限"或"生命值变为固定值"；`modifyField` 受边界限制，用于实现"受到5点伤害"或"增加3点护甲"。

## 6. 玩家（Player）对象 API

在 `action` 中，你经常需要直接操作玩家对象。以下是常用接口：

### 6.1 字段操作

| 方法 | 说明 |
|---|---|
| `player.getFieldValue(name)` | 读取字段当前值。对 `counter` 自动返回所有 `effectId` 之和。 |
| `player.setFieldValue(name, value)` | 设置字段值。**不受 `max/min` 限制**，但会触发 `{name}_change` 事件。 |
| `player.modifyFieldValue(name, delta)` | 修改字段值。**受 `max/min` 限制**。 |
| `player.hasKeyword(name)` | 检查是否拥有某关键词。 |
| `player.setKeyword(name, bool)` | 设置关键词。 |
| `player.ensureFieldExists(name)` | 若字段不存在，根据 `fieldDefinitions` 动态创建。 |
| `player.removeField(name)` | 删除字段。 |

### 6.2 计数器操作（Player 级）

| 方法 | 说明 |
|---|---|
| `player.getCounter(name, effectId)` | 获取指定来源的计数器值。 |
| `player.setCounter(name, effectId, value)` | 设置指定来源的计数器值（下限 `0`）。 |
| `player.modifyCounter(name, effectId, delta)` | 增减指定来源的计数器。 |
| `player.removeCounter(name, effectId)` | 移除指定来源的计数器。若该字段下无计数器，自动删除字段。 |
| `player.getCounterSum(name)` | 获取该字段下所有来源的计数器总和。 |

### 6.3 牌堆操作

| 方法 | 说明 |
|---|---|
| `player.draw(count)` | 抽 `count` 张牌。自动处理疲劳洗牌逻辑。 |
| `player.discardAllHand()` | 弃置所有手牌到弃牌堆。 |
| `player.shuffleDeck()` | 洗切抽牌堆。 |
| `player.getZoneArray(zone)` | 获取区域数组。`zone` 可为 `"deck"` / `"hand"` / `"field"` / `"discard"` / `"banished"`。 |

## 7. 卡牌（CardInstance）对象 API

| 方法 | 说明 |
|---|---|
| `card.id` | 唯一实例 ID。 |
| `card.definition` | 卡牌定义（`CardDefinition`），包含静态字段与能力模板。 |
| `card.owner` | 拥有者（`Player`）。 |
| `card.zone` | 当前区域字符串。 |
| `card.getCounter(name, effectId)` | 读取卡牌上的计数器。 |
| `card.setCounter(name, effectId, value)` | 设置卡牌上的计数器（下限 `0`）。 |
| `card.modifyCounter(name, effectId, delta)` | 增减卡牌上的计数器。 |
| `card.getCounterSum(name)` | 获取卡牌上某计数器字段的总和。 |

### 7.1 卡牌定义（CardDefinition）API

| 方法 | 说明 |
|---|---|
| `cardDef.getCost()` | 获取 `cost` 字段值，若无则返回 `0`。 |
| `cardDef.hasCost()` | 是否声明了 `cost` 字段。 |
| `cardDef.getStaticValue(name)` | 获取静态字段值。 |
| `cardDef.setStaticValue(name, val)` | 设置静态字段值。**不受 `max/min` 限制**。 |
| `cardDef.modifyStaticValue(name, delta)` | 修改静态字段值。**受 `max/min` 限制**。 |
| `cardDef.hasKeyword(name)` | 是否拥有某关键词。 |

## 8. 游戏引擎（GameEngine）全局 API

通过 `ctx.game` 访问。

### 8.1 状态与日志

| 属性/方法 | 说明 |
|---|---|
| `game.player1` / `game.player2` | 双方玩家实例。 |
| `game.currentPlayer` | 当前回合玩家。 |
| `game.turnCount` | 当前回合数（从 `1` 开始）。 |
| `game.gameOver` | 布尔值，游戏是否结束。 |
| `game.log(msg, type)` | 写入日志。`type` 可选 `"system"` / `"damage"` / `"heal"` / `"mp"`，会影响日志颜色。 |

### 8.2 卡牌移动与生命周期

| 方法 | 说明 |
|---|---|
| `game.moveCard(card, toZone)` | 将卡牌移动到指定区域。`toZone` 为 `"deck"` / `"hand"` / `"field"` / `"discard"` / `"banished"`。引擎自动维护数组与 `card.zone` 状态。 |
| `game.createFatigueCard(owner)` | 生成一张"疲劳"卡（不可打出，抽到造成1点伤害）。用于实现自定义疲劳机制。 |

### 8.3 伤害与治疗

| 方法 | 说明 |
|---|---|
| `game.dealDamage(player, amount)` | 对玩家造成伤害。会自动触发 `hp_change` 与后续连锁。若 HP 归零则触发游戏结束。 |
| `game.heal(player, amount)` | 恢复玩家生命。同样触发 `hp_change`。 |

### 8.4 事件派发

| 方法 | 说明 |
|---|---|
| `game.emit(event, context)` | 手动派发事件。可用于自定义连锁或触发额外时机。`context` 需为 `AbilityContext` 实例。 |

### 8.5 选项接口（交互式选择）

引擎支持在 `action` 中**弹出模态框**让玩家进行选择。这些方法是异步的，必须在 `async action` 中使用 `await`。

| 方法 | 说明 |
|---|---|
| `game.showOptions(options)` | 通用选项接口。返回玩家选择的数组，或 `null`（取消）。 |
| `game.selectCards(cards, min, max, title)` | 让玩家从给定卡牌列表中选择。返回 `CardInstance[]` 或 `null`。 |
| `game.selectAbilities(abilities, min, max, title)` | 让玩家从给定能力列表中选择。返回能力对象数组或 `null`。 |

#### showOptions 详细参数

```javascript
await ctx.game.showOptions({
  type: 'cards',           // 'cards' | 'items'
  title: '选择一张手牌丢弃',
  cards: player.hand,      // type='cards' 时必填
  items: [                 // type='items' 时必填
    { id: 0, label: '选项A', data: anything },
    { id: 1, label: '选项B', data: anything }
  ],
  minSelect: 1,            // 最少选择数量
  maxSelect: 1             // 最多选择数量
});
```

- 当 `maxSelect === 1` 时，点击即确认，无需额外点击确认按钮。
- 当 `maxSelect > 1` 时，玩家可点击多项，再点击"确认"。
- 返回值为数组（即使只选一项），若玩家点击"取消"则返回 `null`。

## 9. 内置全局规则（不可覆盖的底层逻辑）

引擎在初始化时会自动注册以下全局能力，其优先级固定，套组设计者应当了解它们的存在：

| 能力名 | 触发事件 | 优先级 | 说明 |
|---|---|---|---|
| `先攻决定` | `game_start` | `100` | 比较双方 `先攻` 字段，高者先手；相同则随机。 |
| `初始抽牌` | `game_start` | `90` | 双方各洗切牌库并抽 `5` 张。 |
| `回合开始资源` | `turn_start` | `80` | 从第 `2` 回合开始，当前玩家弃置所有手牌并重新抽 `5` 张。 |
| `MP恢复` | `turn_start` | `70` | 若玩家拥有带 `max` 的 `mp` 字段，在回合开始时将 `mp` 恢复至 `max`。 |
| `回合检查` | `play_check` | `100` | 若尝试出牌的玩家不是 `currentPlayer`，阻止打出。 |
| `费用检查` | `play_check` | `90` | 若卡牌有 `cost` 字段，检查 `source.mp` 是否足够；不足则阻止。 |
| `费用消耗` | `before_play` | `90` | 在卡牌打出前扣除相应 `mp`。 |
| `使用弃牌` | `after_play` | `0` | 将打出的卡牌从手牌移入弃牌堆。 |
| `疲劳伤害` | `draw` | `50` | 若抽到带有 `疲劳` 关键词的卡，对抽牌者造成 `1` 点伤害。 |
| `疲劳禁止` | `play_check` | `1000` | 带有 `疲劳` 关键词的卡无法被打出。 |
| `生命检查` | `hp_change` | `0` | 若某玩家 `hp <= 0`，触发游戏结束。 |

> **设计提示**：若你想实现"本回合出牌不消耗 MP"或"对手回合也能出牌"等效果，可通过注册同名高优先级能力在 `play_check` 中调用 `ctx.preventDefault()` 来抵消上述内置规则。

## 10. 常见游戏机制实现指南

以下给出可直接复制到 JSON 中的代码模板（注意：JSON 中函数需写成字符串，引擎会自动反序列化）。

### 10.1 造成伤害

```json
{
  "triggers": ["on_play"],
  "action": "async ctx => { await ctx.game.dealDamage(ctx.target, 10); }"
}
```

### 10.2 恢复生命

```json
{
  "triggers": ["on_play"],
  "action": "async ctx => { await ctx.game.heal(ctx.source, 5); }"
}
```

### 10.3 消耗/恢复 MP

```json
// 恢复2点MP（注意：set不受max限制，可直接突破上限；若需约束请用modify）
{
  "triggers": ["on_play"],
  "action": "async ctx => { await ctx.source.setFieldValue('mp', ctx.source.getFieldValue('mp') + 2); }"
}

// 或消耗对手3点MP（modify受min=0限制，不会扣成负数）
{
  "triggers": ["on_play"],
  "action": "async ctx => { await ctx.target.modifyFieldValue('mp', -3); }"
}
```

### 10.4 生成临时卡牌（如 token、复制）

引擎没有直接的"生成卡牌并加入手牌"高级 API，但可以通过手动构造 `CardInstance` 并推入数组实现。由于 JSON 中无法直接引用类名，**推荐通过 `game.emit` 配合全局能力或预置卡牌模板**来实现。若必须在单卡能力中生成，可利用 `ctx.game.createFatigueCard` 作为参考模板，或采用以下模式：

```json
// 在手牌中生成一张"幻影剑"（假设套组中已定义该卡）
{
  "triggers": ["on_play"],
  "action": "async ctx => {
    const def = ctx.game.player1.deck.find(c => c.definition.name === '幻影剑');
    if (def) {
      const token = new CardInstance(def.definition, ctx.source);
      token.zone = 'hand';
      ctx.source.hand.push(token);
      ctx.game.log(ctx.source.name + ' 生成了幻影剑！', 'system');
    }
  }"
}
```

> **注意**：JSON 中写 `new CardInstance(...)` 是合法的，因为引擎通过 `eval` 反序列化函数字符串。但需确保 `CardInstance` 与 `CardDefinition` 类在全局作用域可用（引擎已保证）。

### 10.5 移动卡牌（如弃置、回手、除外）

```json
// 将目标玩家场地最左侧的卡牌除外
{
  "triggers": ["on_play"],
  "action": "async ctx => {
    if (ctx.target.field.length > 0) {
      const card = ctx.target.field[0];
      ctx.game.moveCard(card, 'banished');
      ctx.game.log(card.definition.name + ' 被除外！', 'system');
    }
  }"
}
```

### 10.6 抽牌/令对手抽牌

```json
// 自己抽2张
{
  "triggers": ["on_play"],
  "action": "async ctx => { await ctx.source.draw(2); }"
}

// 令对手抽1张（可能用于爆牌或援助）
{
  "triggers": ["on_play"],
  "action": "async ctx => { await ctx.target.draw(1); }"
}
```

### 10.7 放置/触发计数器（如炸弹、中毒）

```json
// 给对手放置一个倒计时10的炸弹
{
  "triggers": ["on_play"],
  "action": "ctx => {
    const effectId = Math.random().toString(36).substr(2, 9);
    ctx.target.setCounter('炸弹', effectId, 10);
    ctx.game.log(ctx.target.name + ' 被放置了炸弹！倒计时: 10', 'system');
  }"
}

// 全局能力：每回合开始时所有炸弹倒计时-1，归零则爆炸
{
  "triggers": ["turn_start"],
  "priority": 60,
  "action": "async ctx => {
    const bombField = ctx.source.fields['炸弹'];
    if (!bombField || bombField.type !== 'counter') return;
    const values = bombField.values || {};
    for (const effectId of Object.keys(values)) {
      const value = values[effectId];
      if (value > 0) {
        ctx.source.modifyCounter('炸弹', effectId, -1);
        if (ctx.source.getCounter('炸弹', effectId) <= 0) {
          ctx.source.removeCounter('炸弹', effectId);
          await ctx.game.dealDamage(ctx.source, 25);
          ctx.game.log(ctx.source.name + ' 的炸弹爆炸了！受到25点伤害', 'damage');
        } else {
          ctx.game.log(ctx.source.name + ' 的炸弹倒计时: ' + ctx.source.getCounter('炸弹', effectId), 'system');
        }
      }
    }
  }"
}
```

### 10.8 监听任意字段变化并响应

```json
// 当任意玩家的 hp 变化时，若其拥有"吸血"关键词，则恢复1点生命
{
  "triggers": ["hp_change"],
  "priority": 5,
  "condition": "ctx => ctx.target.hasKeyword('吸血') && ctx.data.new < ctx.data.old",
  "action": "async ctx => {
    await ctx.game.heal(ctx.target, 1);
    ctx.game.log(ctx.target.name + ' 的吸血触发了！', 'heal');
  }"
}

// 监听自定义字段 "怒气" 的变化
{
  "triggers": ["怒气_change"],
  "priority": 10,
  "action": "ctx => {
    if (ctx.data.new >= 100) {
      ctx.game.log(ctx.target.name + ' 怒气满值了！', 'system');
    }
  }"
}
```

### 10.9 条件打出（如只能在自己回合受伤后打出）

```json
{
  "condition": "ctx => ctx.game.currentPlayer === ctx.source && ctx.source.getFieldValue('hp') < ctx.source.fields.hp.max",
  "triggers": ["on_play"],
  "action": "async ctx => { await ctx.game.heal(ctx.source, 8); }"
}
```

### 10.10 弹窗选择目标（交互式能力）

```json
// 打出时选择对手场地一张卡将其破坏
{
  "triggers": ["on_play"],
  "action": "async ctx => {
    if (ctx.target.field.length === 0) return;
    const selected = await ctx.game.selectCards(ctx.target.field, 1, 1, '选择要破坏的卡牌');
    if (selected && selected.length > 0) {
      const card = selected[0];
      ctx.game.moveCard(card, 'discard');
      ctx.game.log(card.definition.name + ' 被破坏送入弃牌堆', 'system');
    }
  }"
}
```

### 10.11 打出康（Counter）

通过 `before_ability_execute` 拦截特定能力：

```json
// 当对手尝试执行造成伤害的能力时，若自己场上有"魔法盾"，则阻止之
{
  "triggers": ["before_ability_execute"],
  "priority": 999,
  "condition": "ctx => {
    const ab = ctx.ability;
    const isDamage = ab && ab.name && ab.name.includes('伤害');
    const hasShield = ctx.actor.hasKeyword('魔法盾');
    return isDamage && hasShield && ctx.actor !== ctx.source;
  }",
  "action": "ctx => {
    ctx.preventDefault('魔法盾抵消了伤害能力');
    ctx.actor.setKeyword('魔法盾', false);
    ctx.game.log(ctx.actor.name + ' 的魔法盾发挥了作用！', 'system');
  }"
}
```

## 11. 序列化与函数书写规范

由于套组文件是 JSON 格式，所有函数（`condition`、`action`）必须写成**字符串**。引擎加载时会自动通过 `eval` 还原为函数。

### 11.1 书写规则

1. **箭头函数**：推荐写成箭头函数字符串，如 `"async ctx => { ... }"`。
2. **普通函数**：也可写成 `"function(ctx) { ... }"` 或 `"async function(ctx) { ... }"`。
3. **引号处理**：JSON 中字符串使用双引号，因此函数体内的字符串应使用**单引号**或**转义双引号**。
4. **分号**：函数体中建议使用分号或确保自动分号插入不会导致解析错误。

## 13. 调试与异常处理

- 引擎内置全局异常兜底：若某个 `action` 抛出异常，游戏不会崩溃，而是会在日志区显示红色错误提示，并弹出 Toast 说明出错的能力名称与事件名。
- 建议在设计套组时打开浏览器开发者工具（F12）的 Console，查看详细堆栈。
- 若函数字符串存在语法错误，加载套组文件时会弹出 `alert` 提示解析失败。
